# Level3 クラウド設計思考実験：机上設計評価

日本語 | [English](README.md)

## 目的

曖昧な業務要件から、AIエージェントが AWS/Azure/GCP の妥当な設計を導き、固定した採点基準で評価されるかを調べた実験の記録です。採点対象の10月の試行は机上設計で、環境の構築や、実インフラの性能・復旧・請求の実測は行っていません。9月のC-1では、既存の認証済みコンソールを読取専用で確認しましたが、変更は行わず未完了で停止しました。読むだけならクラウドへのアクセスは不要です。ローカルでの文書・実装作業はインフラの受入れではなく、設計文書の評価だけでは、実インフラ、SLO達成、削除の実行、請求額、法令適合は証明できません。

## 二つの研究フェーズ

- **9月：初回の試み（自己評価）。** A-1（9/8）、A-2/A-3（9/9）、B（9/10）の自己採点は、A 61 → 65、B 66。報告書自体が不足を記録しています：監視費の漏れ、そして削除期限・復旧・担当体制の制約が未実証でした。C-1（9/13）は未完了で停止。10月とは方法が異なり、点数は比較できません（[A](experiments/A/final-report.md)、[B](experiments/B/final-report.md)、[C-1](evaluation/C-1-console-readonly-check-run.md)）。
- **10月：独立した追試（10/1〜10/2）。** 自己採点を独立レビューに置き換えました。要件と証拠の対応づけ、未確定費用（U）の台帳、IAM・削除・復旧の具体化は進みましたが、実環境での証明はありません。独立評価の最高点はD4の78、最新はD5の77（要求はHigh）です。別の新規試行（73）と未採点の変更要件はこの系列に含めません。実際のモデルと適用された推論設定は不明です。
