# Level3 価格モデルと未価格項目

確認日：2026年10月2日（日本時間）。公開オンデマンド価格、USD税別。無料枠、期間限定credit、長期契約割引は使用しない。単価は確認時点の証拠であり、将来の請求額の保証ではない。

## 1 比較条件

- 主系を東日本、副系を西日本、月730時間の課金換算。開発は本番から分離し40時間の稼働仮定
- 通常10RPSは24時間。100RPSの15分peakは通常10RPSの時間を置き換えるものとして計算する。100RPSが追加分という意味なら再計算が必要
- 登録1万人、業務20GB＋月2GB、画像100GB＋月10GB、外向き200GB/月は正式シナリオ値。MAU、mail数、CPU処理時間、DB確保容量、WAL量は別の入力
- 静的要求と動的要求、通常月とlaunch期、1000RPS試験は別計上
- 14日PITRと90日backup、国内の複製、監視・認証・鍵、失敗/復元時の一時資源を含める。ただし取得できなかった単価・数量はU（未確定）

## 2 リクエスト数量

通常件数＝10×3600×730＝26,280,000件。100RPS peak1回の増分＝(100−10)×900＝81,000件。

| シナリオ | peak回数 | 動的件数/月 | 用途 |
|---|---:|---:|---|
| 通常のみ | 0 | 26,280,000 | 基準 |
| 定常 | 4 | 26,604,000 | 承認された初期計算仮定 |
| launch日1回相当 | 30 | 28,710,000 | 30回の感度。730時間と暦月30日の差を承知した比較値 |
| launch日3回相当 | 90 | 33,570,000 | 「数回」の具体化例であり予測ではない |

1000RPS・15分は900,000件の独立負荷。月額へ含めるなら実施回数、実行環境、通常負荷との重複、cleanup時間を別に入力する。PV100万/月と動的要求2,628万/月の関係は未検証。保守的なRPS計算を採用し、PVから値を引き下げていない。

## 4 DBの条件付き部品価格

**以下のDBは性能・memory・CPU特性が等価ではない。金額を並べて採用順位を決めてはならない。** 小計は、具体的な部品表で計算を再現できることを示すために掲載する。必要最小費用の厳密な下限ではない。

### AWS RDS案

Auroraとは別の比較候補。PostgreSQL db.t4g.mediumは2vCPU/4GiBのburstable。東京Multi-AZ $0.202/時＋大阪Single-AZ read replica $0.101/時を各730時間。開発東京Single-AZ同型40時間を$0.101/時で計上。

DB compute＝730×(0.202＋0.101)＋40×0.101＝**$225.23/月**。

アプリ共通例との既価格小計＝**$317.66/月**。DB storage、backup、地域間転送、CPU credit追加課金、LB等は未計上。大阪の地域内HAも含まない。小型burstableが継続10RPS・100RPS peakのDB負荷に足りるかは不明。

### Azure PostgreSQL案

Flexible Server Standard_D2ds_v5、東は$0.244/時、西は$0.265/時。東のHAをprimaryとstandbyの2台で計上、西read replica1台を730時間。開発は東同型1台40時間。

DB compute＝730×(2×0.244＋0.265)＋40×0.244＝**$559.45/月**。

アプリのactive共通例と定常動的要求料金を加えた既価格小計＝**$732.0916/月**。storage、backup、外形監視、private endpoint/管理機能、地域間転送、認証等は未計上。西側HAは未計上。

Flexible Server storageの公開単価は東西とも通常Storage Data Storedが$0.138/GB月、backup LRSが$0.095/GB月だった。ただしDBの論理20GBは確保storageと同一ではなく、HAのcopies、backupの包含枠と追加使用量、長期backup経路も未確定なので小計に足していない。古いSingle Serverや別製品の同名meterは混用しない。

### GCP Cloud SQL案

14日PITRとAdvanced DRを前提にEnterprise Plusを候補とする。現行日本DB料金は取得できなかった。旧記録の東京単価は見つかったが、現行値・大阪値として使用していない。アプリ$118.80＋DB compute U＋残りの項目Uとする。空欄をゼロとしてAWS/Azureより安いと判定しない。

## 5 全込み月額の式

全込み税前額＝アプリ＋東HA DB＋西DB＋開発compute＋storage＋14日PITR＋90日backup＋画像配信/外向き通信＋地域間通信＋LB/DNS/WAF/私設経路＋認証/mail＋監視/log/鍵＋復旧/削除処理＋一時/残存資源。

USDモデルなら、税込見積＝全込みUSD×請求FX×適用税係数＋変動余裕。JPY請求の場合は実際のJPY SKU・契約条件を用いる。現在の市場FXを実請求FXと同一視しない。適用税、為替、余裕率は未確定のまま明記し、任意の値で予算適合を作らない。

| 必須項目 | 数量と価格の入力 | 未確定が費用へ与える影響 |
|---|---|---|
| アプリ/DB容量 | CPU・memory、台数、性能試験、接続数、burst時間 | 主系2台や西HAなら固定費増加 |
| DB storage | 20GB＋増分、index、空き、確保単位、地域内/地域間copies | 論理容量だけでは見積不可 |
| PITR/backup | 日次変更、WAL、圧縮/重複除去、90日使用量、国内copies | 20GB×90と単純計算せず実方式へ合わせる |
| 画像/通信 | 100GB＋増分、200GB外向き、cache率、要求数、地域間copy | CDN・ネットワーク・request課金を区別 |
| 認証/mail | MAU、login方法、送信数、保存場所、追加addon | 登録1万人から自動決定しない |
| 運用基盤 | log GB/保持、metrics、probe、鍵、秘密、監査、復旧制御 | 平時費用と事故時増分を両方含める |
| 開発/試験 | 40時間、停止時storage、起動制約、試験用複製 | compute停止だけでゼロにならない |
| 復旧/失敗 | 一時DB二重起動、snapshot/通信、cleanup待機 | 初月・事故月の上振れ |
| 請求 | 売主通貨、税、FX、余裕、非停止課金 | 最終的な税込上限との比較が必要 |

## 6 予算に関する判定

3社の全込み価格比較は未完。税込初月20万円・以降10万円への適合は判定できない。AWSの$317.66、Azureの$732.0916は、選んだ異なるDB部品の部分小計にすぎない。

Azure例はDB computeの固定費が大きく、残りの必須費用を先に確認する価値がある。AWS例は安さより先にburstable性能と無人地域切替制御を確認する。GCP例はDBと国内認証の価格・適合確認が必要である。これは検討順の提案で、予算超過や採用を断定するものではない。

人件費、ドメイン取得更新、有料人的サポートは合意されたインフラ枠外。別費目として必要性を残し、無償と扱わない。今回の成果は、数量式と検証できた部品価格、未価格項目を残した最終机上モデルまでである。
