# Migration stages, identity/session and deletion-ledger rollback

REQ-18/24 portability proposal for a separately authorized migration. No migration/rehearsal/provider choice occurs now. OCI/SQL core is portable; IAM/network/identity/session/queue/key/deletion semantics are not. All windows/thresholds conditional and require capacity/cost/authority; original source requirements stay fixed. An unanswered identity export/password/session capability may require user reauthentication/password reset; do not claim credential portability or send raw passwords/tokens to a new provider.

Session acceptance cannot be reduced to attribute count: verify token audience/issuer/signature/JWKS TTL/expiry, refresh revocation, admin MFA and subject mapping. Where passwords cannot export in a safe supported format, use owner-approved password reset and fail closed; lost logged-in sessions affect principal availability and must be measured. Reauthentication does not revoke old credentials by itself. Deletion ledger transfer includes pending cases and all receipts through tp, not only closed cases or hourly snapshot; independent ingress receipt chain must survive old-provider failure. If reverse identity or journal mapping cannot establish exact subject ownership/deletion completeness, postwrite rollback is unsafe even with matching SQL rows.

Costs: C11 duplicate app/coordinator/broker/SQL quarantine hours, C04 object versions/copies, C06 private path/cross-provider/interregion transfer, C07 duplicate-suppressed outbox/queue, C08 dual identity/key/secret operations, C09 probes/audit/ledger, C10 state/registry, C12 approved DR copy plus outside-cap40–80h work. No prepaid/free-tier offset. Proposed24h hold/2day temporary object scope must be replaced by approved measured duration; charges persist for retained disk/IP/keys/backup/logs. A failed checkpoint adds overlap; quoteU means total/headroomU.
